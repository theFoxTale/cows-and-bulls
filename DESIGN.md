# DESIGN.md — Bulls and Cows

Документ описывает архитектурные решения проекта: структуры данных, алгоритмы ядра игры, оценку сложности и применение принципов чистого кода.

---

## 1. Структуры данных

### 1.1. Секретное число

**Структура:** `string` (строка символов), а не `number`.

**Почему:**

- Число из уникальных цифр в произвольной системе счисления может начинаться с нуля (`0123`, `00FF`), а `Number` теряет лидирующие нули.
- Строка удобна для посимвольных операций (`filter`, `map`, `includes`) без арифметики.
- Символы приводятся к нижнему регистру (`toLowerCase`) при сравнении — так `a` и `A` в hex считаются одной цифрой.

## 2. Алгоритмы

### 2.1. Алгоритм `evaluateGuess(secret, guess)`

**Цель:** вернуть `{ bulls, cows }`.

1. **Bulls** — позиции, где `secret[i] === guess[i]` (с приведением к нижнему регистру). Считаются через `filter` по индексам и `.length`:
   ```ts
   const bullsCount = guessArray.reduce((sum, digit, index) => {
     return sum + (digit === secretArray[index] ? 1 : 0);
   }, 0);
   ```
2. **Cows** — символы, которые есть в секрете, но не на своей позиции. Считаются через `reduce`:
   - для каждого символа попытки, который **не** является bull-ом,
   - проверяем, есть ли он в «остатке» секрета (символы секрета, не участвующие в bull-ах),
   - если есть, увеличиваем счётчик и «вычёркиваем» его из остатка, чтобы не посчитать дважды.
   ```ts
   const cowsCount = guessRest.reduce((sum, digit) => {
     const firstIndex = secretRest.indexOf(digit);
     if (firstIndex === -1) return sum;

     secretRest.splice(firstIndex, 1); // локальная копия, не мутирует secret
     return sum + 1;
   }, 0);
   ```
   > `splice` здесь мутирует **локальную копию** `secretRest`, а не входные данные — чистота функции сохраняется.

### 2.2. Алгоритм `countPossibleSecrets(length, base)`

**Формула:** количество перестановок без повторений `P(base, length) = base × (base − 1) × … × (base − length + 1)`.

**Рекурсивная реализация:**

```ts
const countPermutations = (n: number, k: number): number => {
  if (k === 0) return 1;
  if (k > n) return 0;

  return n * countPermutations(n - 1, k - 1);
};
```

**Почему рекурсия уместна:**

- Формула рекурсивна по своей природе: «выбрать первую цифру из `base`, затем посчитать перестановки длины `length − 1` из оставшихся `base − 1` цифр».
- База `length === 0` возвращает `1` — пустая перестановка одна.
- Защита `length > base` даёт `0`, потому что нельзя выбрать больше уникальных цифр, чем есть в алфавите.

**Мемоизация:** обёртка `cache` кэширует результаты в `Map` по ключу `${length}_${base}`. Функция вызывается при каждом открытии экрана настроек, пересчитывать факториалы каждый раз — расточительно, особенно для `hex` + `length = 6` (`P(16, 6) = 5 765 760`).

## 3. Сложность (Big O)

Обозначения: `L` — длина секрета (2–6), `B` — основание системы счисления (2–16). Для всех функций ядра `L` и `B` — малые константы, поэтому на практике всё работает за «почти O(1)», но асимптотически:

| Функция                                | Время                                                               | Память   | Обоснование                                                                                                                                                                                                                                                                                                                                            |
| -------------------------------------- | ------------------------------------------------------------------- | -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `generateSecret(length, base, random)` | **O(B + L) → O(B)**                                                 | **O(B)** | `getBaseData` — O(1); `allowed.split('')` — O(B); цикл Фишера–Йетса по `L` итерациям с O(1) на шаг — O(L); `slice + join` — O(L). Так как `L ≤ B`, итого O(B). Память — массив `digits` длины B + строка результата длины L (O(L) ⊆ O(B)).                                                                                                             |
| `evaluateGuess(secret, guess)`         | **O(L²)**                                                           | **O(L)** | `toLowerCase/split` — O(L); `reduce` по быкам — O(L); два `filter` — O(L); `reduce` по коровам: внутри `secretRest.indexOf(digit)` — O(L), `splice` — O(L). Итого O(L × L). Память — четыре временных массива (`secretArray`, `guessArray`, `secretRest`, `guessRest`) длины ≤ L.                                                                      |
| `isValidGuess(guess, length, base)`    | **O(L × B) → O(L) при фиксированном B**                             | **O(L)** | Проверка длины — O(1); нормализация и `split` — O(L); `every(isValidDigit)` — L вызовов, каждый делает `allowedDigits.includes(...)` за O(B), итого O(L × B); `new Set(...)` — O(L). При `B ≤ 16` практически линейно. Память — нормализованная строка, массив символов и `Set` длины ≤ L.                                                             |
| `countPossibleSecrets(length, base)`   | **O(L)** без мемоизации на один вызов; **O(1)** при попадании в кэш | **O(L)** | Проверки и `getBaseData` — O(1); `countPermutations(base, length)` — рекурсия глубины `L`, на каждом уровне O(1) арифметики. Повторный вызов с теми же аргументами возвращается из `Map` за O(1). Память — стек рекурсии глубины `L`; кэш ограничен числом уникальных пар `length`/`base` (≤ 5 × 4 = 20 записей), то есть O(1) относительно `L` и `B`. |

**Вспомогательные функции (для полноты):**  
`createDigitValidator(base)` — создание **O(1)**, вызов валидатора **O(B)** по времени, **O(1)** по памяти (замыкание хранит ссылку на строку `allowed`).  
`getBaseData(base)` — **O(1)** по времени и памяти (поиск по массиву из 4 конфигураций).

## 4. Принципы чистого кода

### 4.1. Чистые функции (Pure Functions)

**Где:** всё ядро игры — `src/core/generate-secret.ts`, `src/core/evaluate-guess.ts`, `src/core/is-valid-guess.ts`, `src/core/create-digit-validator.ts`, `src/core/count-possible-secrets.ts`.

**Что это даёт:**

- Нет обращений к DOM, `localStorage`, `Date.now()` внутри ядра — всё это передаётся параметрами.
- `generateSecret(length, base, random = Math.random)` принимает источник случайности — в тестах передаём детерминированный `random`, в UI — `Math.random`. Функция остаётся чистой и тестируемой.
- `evaluateGuess(secret, guess)` не читает глобальное состояние — результат зависит только от аргументов.

### 4.2. Функции высшего порядка (HOF)

**Где:**

- `evaluateGuess` — `filter` + `reduce` вместо `for`-циклов.
- `isValidGuess` — `every` для проверки всех символов через валидатор.

### 4.3. Каррирование

**Где:** `src/core/create-digit-validator.ts` — `createDigitValidator(base)` → `(char) => boolean`.

**Что это даёт:**

- Функция-предикат «этот символ — допустимая цифра в этой системе» создаётся один раз под конкретный раунд и переиспользуется в двух местах:
  1. **Валидация попытки** — `isValidGuess` вызывает `every(createDigitValidator(base))`.
  2. **Фильтрация ввода в реальном времени** — на `input`-событии `char => validator(char)` блокирует недопустимые символы в поле ввода.
- Каррирование позволяет «зашить» `base` в функцию и передавать её как колбэк в HOF, не таща `base` через все вызовы. Ну и дополнительно усложнить код, чтобы через месяц его уже никто не понял. :)

### 4.4. Мемоизация

**Где:** файл `src/core/count-possible-secrets.ts`, обёртка `countPermutations` и оборачиваемая функция `countPossibleSecrets`.

**Что это даёт:**

- `countPossibleSecrets(6, 16)` = `5 765 760`, считается рекурсивно один раз; при повторном открытии экрана настроек возврат из `Map`-кэша за O(1).
- Кэш реализован через `Map<string, number>`, ключ — `${length}_${base}`, что безопаснее объектов (не конфликтует с `__proto__` и т.п.).

### 4.5. Рекурсия

**Где:** файл `src/core/count-possible-secrets.ts`, `countPermutations` — рекурсивная формула `base × P(base − 1, length − 1)`.

**Почему не цикл:** рекурсивная форма напрямую отражает математическое определение перестановки без повторений и читается ближе к формуле `P(n, k) = n! / (n − k)!`. Глубина рекурсии ограничена `length ≤ 6` — переполнения стека не будет.
